# dslcap 工具

`dslcap` 工具不使用主視窗，從 DSLogic 裝置擷取資料。在指令碼和自動測試中使用它。此工具把取樣寫入一個二進位檔案。它把一個包含結果的 JSON 物件寫到標準輸出。

此工具位於應用程式套件中：

```sh
"/Applications/Logic Analyze.app/Contents/MacOS/dslcap"
```

> [!NOTE]
> 同一時間只有一個程式可以使用裝置。使用 `dslcap` 之前，結束 Logic Analyze。

## 列出裝置

要列出程式庫可以找到的裝置，輸入以下指令：

```sh
dslcap --list
```

要列出每個已連接的 DSLogic 裝置的 USB 識別碼，輸入以下指令：

```sh
dslcap --list-ids
```

`--list-ids` 指令只讀取 macOS 保存的 USB 裝置資訊。它不向裝置傳送資料。輸出提供每個裝置的型號、USB 位置和登錄識別碼。

## 擷取資料

此指令在通道 0 和 1 上以 10 MHz 擷取 1000000 個取樣：

```sh
dslcap --channels 0,1 --samplerate 10000000 --samples 1000000 --out /tmp/capture
```

此工具把取樣寫入 `/tmp/capture.bin`。如果已有同名檔案，工具顯示錯誤並停止。此工具不取代檔案。

擷取選項如下：

| 選項 | 功能 | 初始值 |
| --- | --- | --- |
| `--channels LIST` | 要記錄的通道，例如 `0,1,2`。 | `0` |
| `--samplerate HZ` | 取樣率，單位為 Hz。 | `10000000` |
| `--samples N` | 每個通道的取樣數。 | `1000000` |
| `--vth VOLTS` | 臨界電壓。 | `1.6` |
| `--mode MODE` | `buffer` 或 `stream`。 | `buffer` |
| `--trigger CH[:T]` | 通道 CH 上的觸發。T 使用 `R`（上升緣）、`F`（下降緣）、`C`（上升緣或下降緣）、`1`（高準位）或 `0`（低準位）。 | 無觸發。只提供 CH 時為 `R`。 |
| `--trigpos PERCENT` | 觸發位置，為取樣數的百分比。 | `10` |
| `--timeout SEC` | 擷取的最長時間，單位為秒。 | `30` |
| `--out PATH` | 輸出檔案的路徑，不含 `.bin` 副檔名。 | 必須使用此選項。 |
| `--log-level N` | 標準錯誤輸出上程式庫訊息的數量，從 0（無）到 5（全部）。 | `1` |

此工具在使用裝置之前檢查所有選項。如果某個選項不正確，工具停止並顯示錯誤。

## 輸出檔案

`.bin` 檔案依通道編號由小到大的順序包含各通道。對於每個通道，檔案包含該通道的所有取樣。每個位元組保存 8 個取樣。第一個取樣是最低有效位元。每個通道的資料填滿整數個 8 位元組單位。因此，每個通道使用 `ceil(samples / 64) × 8` 位元組。

## JSON 結果

此工具在一行中寫入一個 JSON 物件。擷取正確時，該物件提供裝置名稱、取樣率、取樣數和通道。它還提供臨界電壓、模式、觸發、擷取時間和 `.bin` 檔案的路徑。如果擷取不正確，該物件包含 `error` 鍵。此時工具不產生 `.bin` 檔案。

只在結束狀態為 0 且 JSON 物件完整時使用結果。

## 結束狀態

| 狀態 | 意義 |
| --- | --- |
| 0 | 擷取完成。 |
| 1 | 操作期間發生錯誤，例如 I/O 錯誤。 |
| 2 | 選項不正確，或裝置上沒有該設定。 |
| 3 | 擷取沒有完成。 |

## 用於啟動 dslcap 的程式的選項

- `--parent-fd N`：啟動此工具的程式關閉描述元為 N 的管道時，工具停止。如果擷取沒有完成，工具隨後刪除其輸出檔案。
- `--res DIR`：存放韌體檔案的資料夾。通常，工具自動找到此資料夾。您也可以設定 `DSLCAP_RES` 環境變數。
- `--res-manifest FD`：工具在把每個韌體檔案傳送到裝置之前，檢查該檔案的 SHA-256 值。

原始碼中的 `tools/dslcap/README.md` 檔案提供這些選項的完整說明。
